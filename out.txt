## 7.2 Model Complexity and Hyperparameter Variations

### Boosting vs. bagging

| | Random Forest (Week 6) | Gradient Boosting (Week 7) |
|---|---|---|
| How trees are built | In parallel, each on a random sample of the data | One after another, each fit to the previous trees' errors |
| Individual trees | Deep, low bias, high variance | Shallow "weak learners," high bias |
| How the ensemble improves | Averaging many trees reduces variance | Each new tree reduces bias |
| Main overfitting risk | Trees grown so deep they memorize the data | Too many trees, too high a learning rate, or trees that are too deep |

**Bias-variance tradeoff.** A Random Forest gets its accuracy by averaging away variance, so its error mostly depends on how expressive each tree is. Boosting works the other way around: it starts with a simple, high-bias model and lowers the bias with every tree it adds. This means every added tree makes the model more flexible, so training performance can keep rising while validation performance eventually stops improving or gets worse. That matters for us because Week 6 already showed our models overfitting to the operating class. With so few IPO, acquired, and closed companies, a boosted model could keep fitting noise in those small classes and push training scores up without helping on validation.

### Hyperparameters we vary

- `learning_rate`: how much each new tree is allowed to change the predictions. Small values learn slowly and cautiously. Large values fit quickly and overfit more easily.
- `max_depth`: how deep each tree can grow, which controls how complicated the patterns inside one tree can be. Deeper trees can capture interactions, such as funding amount together with country, but they can also memorize individual companies.
- `max_iter`: the number of boosting rounds (trees). This is the same idea as `n_estimators` in Random Forest. More rounds give the model more total capacity.

These three work together. A low learning rate needs more trees to reach the same fit, and deeper trees need fewer. We move all three together from conservative to aggressive, so V1 to V3 represents increasing model capacity, as it did in Week 6.

| Variation | Description | learning_rate | max_depth | max_iter |
|---|---|---|---|---|
| V1 - Shallow | Conservative: small steps, simple trees, few rounds | 0.05 | 3 | 100 |
| V2 - Moderate | Middle ground | 0.10 | 6 | 200 |
| V3 - Deep | Aggressive: big steps, deep trees, many rounds | 0.20 | 8 | 300 |

### Settings held constant

- `class_weight='balanced'`, with weights calculated from the training rows.
- `random_state=42`, the same seed as Week 6.
- `max_leaf_nodes=None`. By default this model stops trees at 31 leaves, which would quietly limit `max_depth` for V2 and V3. Removing the cap means `max_depth` is the only thing controlling tree size.
- `early_stopping=False`. By default this model starts holding out part of the training data and stops early once a dataset is larger than 10,000 rows

## 7.6 Summary Report

### Why We Chose Gradient Boosting
In Week 7 we evaluated `HistGradientBoostingClassifier` to test whether sequential boosting could improve on our Week 6 Random Forest results—specifically on minority class detection:

* **Sequential Error Correction:** Unlike Random Forest, which averages independent deep trees, Gradient Boosting builds shallow trees one after another. Each new tree focuses directly on the errors made by the previous ensemble, forcing later trees to pay continuous attention to hard-to-classify IPO, acquired, and closed startups.
* **Fast Histogram Binning on Mixed Data:** `HistGradientBoostingClassifier` buckets continuous features into 255 bins before finding splits. Because 46 of our 51 features are already 0/1 binary flags (country, industry, and missingness indicators) and the remaining 5 are continuous PCA components, histogram binning trains rapidly with virtually zero loss in split precision.
* **Consistent Imbalance Handling:** Like Random Forest, it natively supports `class_weight='balanced'`, allowing us to penalize minority-class errors using our training-set weights (IPO 12.58 vs. operating 0.31) without generating synthetic SMOTE rows across binary flags.

### Hyperparameters and Model Complexity
In Gradient Boosting, complexity is governed by the interaction of step size, tree depth, and the number of boosting rounds. We varied all three together while holding `max_leaf_nodes=None`, `early_stopping=False`, `class_weight='balanced'`, and `random_state=42` constant across our 29,782 training rows and 9,928 validation rows:

* **`learning_rate` (0.05 → 0.10 → 0.20):** Controls how strongly each tree adjusts the ensemble's predictions. Lower rates learn cautiously; higher rates fit training residuals faster but risk memorizing noise.
* **`max_depth` (3 → 6 → 8):** Limits the interaction depth of each weak learner. Depth 3 captures only simple splits, while depth 8 allows complex multi-feature rules.
* **`max_iter` (100 → 200 → 300):** The total number of sequential trees added to the ensemble.

### Evaluation Metrics
Because 81.7% of companies are still operating, raw accuracy rewards models that ignore acquisitions, closures, and IPOs. We evaluated models using:
* **Macro F1 (Primary Metric):** Weights all four outcomes equally, penalizing both underfit models that spam minority predictions and overfit models that default to "operating."
* **Per-Class Recall & Precision:** Recall measures what fraction of actual outcomes we catch, while precision (added in Week 7) measures how trustworthy those predictions are—exposing models like V1 that achieve high IPO recall (0.727) only by suffering low IPO precision (0.123).

# MLPClassifier runs its forward/backward passes as NumPy matmuls, which dispatch
# to multithreaded BLAS. Floating-point addition is not associative, so the order
# the threads reduce in - and therefore the last bit of every result - depends on
# how they happen to interleave. `random_state` fixes the weight init and the
# batch shuffling, but it has no say over that. Across 300 Adam epochs with almost
# no regularization (V3 uses alpha=1e-6) those last-bit differences compound into
# a measurably different model: V3's validation macro F1 moved by ~0.005 between

# and HistGradientBoosting use sklearn's own deterministic kernels, not BLAS

#

It is important to remember that what we did is a capacity proxy and not a universal complexity scale. We do acknowledge that a tree node and a network weight are not the same kind of thing. We note that important caveat here so the Week 9 chart is read as *within-this-study* ordering rather than a claim that an MLP weight and a tree node are interchangeable.

## 9.2 Bias-Variance Chart and Analysis

This section plots train and validation log loss for all nine models from the 9.1 table, ordered by `complexity_rank`. Every number comes straight from `eval_table_w9`, so nothing here is rescored. Each model's column is shaded by which region it falls in. A model underfits when its training log loss is still high (above 0.9) and the gap is tiny (below 0.1). It overfits when validation log loss sits well above training (gap above 0.4), and anything in between is the sweet spot. The dashed line is the log loss of guessing 25% for every class (ln 4 = 1.386), so any point above that line is worse than a blind guess.
